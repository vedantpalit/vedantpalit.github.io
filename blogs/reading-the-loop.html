Reading the Loop: Do looped transformers think in words internally?

TL;DR A looped transformer works out reasoning steps in words inside its loop, without writing them down. A chain-of-thought monitor can only check the reasoning a model writes down. A looped transformer runs its middle layers several times for each token, so it can reason more before it writes anything. In standard transformers, the Jacobian lens translates hidden states into words, which shows the words each hidden state verbalizes. We fit one lens for each pass of the loop in Inkling 2 Mini and TML-d24-varloop-research, and use it to read what each pass holds. The loop holds intermediate steps that the model never writes. For example, when asked for the chemical symbol of the metal with atomic number 79, the model answers “Au” and never writes “gold”, but inside the loop “gold” is the strongest reading of the lens by the second pass. The second pass hands such steps to the third through the message between them, and editing them on the third pass changes the answer. A monitor that reads the loop can see reasoning steps that the chain of thought leaves out.

Writes Au, verbalizes gold

The skipped step is named inside. Asked for the symbol of element 79, the model writes “Au”. Inside the loop, under “79”, it verbalizes “gold”, and it never writes it.

Half the writing

More passes, less chain of thought. On hard math, the same model run with 3 passes instead of 1 writes half as much reasoning and solves more problems (72% → 90%).

Edit the hidden step

The hidden step drives the answer. Push another country into the loop's third pass and the model answers for that country.

Introduction

Reasoning models produce a chain of thought (CoT) before they answer a hard question. The CoT has become one of the main ways to check what a model is doing: when a model plans to exploit a flaw in its task, the plan often appears in its CoT, where a monitor can catch it [1][2]. This check needs the reasoning trace to be available, and it is becoming less so: frontier models write shorter chains of thought, reason more within a single forward pass, and are harder to monitor from the text [3].

Looping is one way to make a model reason more within a single forward pass. A looped transformer applies the same block of layers several times for each token it produces, so it can do more computation before it writes anything, without adding parameters. The idea goes back to the Universal Transformer [4], and recent recurrent-depth models scale up reasoning by running more loops instead of writing more tokens [5]. Inkling 2 Mini, an open production model, runs its 12 middle layers three times. On TML-d24-varloop-research, a research model with the same architecture, three passes instead of one cut the CoT on GPQA Diamond by more than half [6].

Monitoring tests on looped models give mixed results. On some tasks deeper loops make the CoT less useful to a monitor, but looped models are not uniformly less monitorable than standard ones [7], and Inkling 2 Mini shows no meaningful drop in monitorability [6]. These tests only see the text, so we look inside the model.

Inside a standard transformer, the words that hidden states verbalize form a “global workspace” [8], which works like the scratchpad a person keeps in their head. For instance, if I were to work out 17 × 24 in my head, I would hold 340 and 68 in mind, add them, and say 408. Anyone listening would hear only 408. The Jacobian lens reads the model’s version of those held numbers from its hidden states, as words [8]. We read this scratchpad in a looped transformer, to see what it holds on each pass and how much of the unwritten reasoning it carries.

We study the loops of Inkling 2 Mini and TML-d24-varloop-research. TML-d24-varloop-research runs anywhere from 1 to 5 passes [9], so we can change the number of passes and keep everything else fixed. We read each pass with the Jacobian lens, check the readings with linear probes and activation patching, and edit the loop directly, to answer four questions:

  • Does the loop hold reasoning steps that never appear in the CoT or the answer?
  • How do these steps get from one pass to the next?
  • Does the model use these hidden steps to reach its answer?
  • When the model runs more passes and writes a shorter CoT, do the skipped steps move into the loop?

Reading the loop

We read the loop by translating the hidden states of every pass into words, with a separate Jacobian lens for each pass.

Inkling 2 Mini has 24 layers, grouped into four six-layer blocks [6]. The first block, the prelude, runs once and reads the prompt. The two middle blocks form the loop and run three times with the same weights. The last block, the coda, runs once and produces the next token. Each pass starts again from the prelude's output. From the second pass on, the loop also receives a message from the pass before, which a learned gate mixes into its input. Each token goes through 48 layer applications made from 24 stored layers, and none of the intermediate work appears in the output.

The simplest tool for reading this intermediate work is the logit lens [10], which applies the model’s own output layer to a hidden state and takes the words it scores highest. In a standard transformer it reads the later layers reasonably well, because their states are already close to an output. Inside a loop they are not. A state halfway through the second pass is the input for the third pass, and the logit lens reads it as noise.

Why the logit lens fails inside the loop

The logit lens applies the output layer directly to a hidden state, as if nothing came between them. Inside the loop, a lot comes between them.

The output layer is built to read the coda’s output, not a state halfway through the loop. Read directly, a state in the loop gives the same commas, spaces and 的 whatever the text is about.

The Jacobian lens [8] instead carries the state to the output first, using the average linear response of all the layers after it, and then applies the output layer. For a hidden state ha at layer application a:

ℓa(ha)=WUJaha,Ja=𝔼x[∂hfinal∂ha]

WU is the model’s output layer (the unembedding), Ja the Jacobian of the final hidden state with respect to ha, averaged over prompts x, and ℓa the resulting scores over the vocabulary.

We say a hidden state verbalizes a word when the lens gives that word one of its highest scores, relative to the word’s average score on ordinary text. Each pass needs its own lens, because the steps after a layer differ from pass to pass. A layer’s lens on the first pass is almost unrelated to its lens on the third, although the weights are the same, and its lens on the second pass, one gate away from the third, lies in between.

We test the lenses on the question “The ocean on the coast of the country where Carnival is most famously celebrated is the ____”. The model never writes the middle step, Brazil. The lenses read Brazil at the word “celebrated” from the second pass on. On the third pass, the word verbalizes Brazil in other languages, as ברזיל, 브라질 and البرازيل. Most readings on that pass are not in English, so we show each one with its nearest English word in the model’s vocabulary.

We observe that readings inside the loop are often not in English. This differs from Llama-2, whose middle layers favour the English version of a concept [11]. In the loop of TML-d24-varloop-research, on GPQA questions, readings are in other languages as often as in English on every pass, and English takes over only after the loop. Concepts can be represented separately from the language they are written in [12], and the loop seems to work with them at that level. A monitor that reads the loop therefore has to recognise a concept in any language, not search for English words.

The lens inside the loop

Write e for the prelude's output, F for one pass through the twelve shared layers, g for the gate that turns a pass into a message for the next, and C for the coda. Every pass starts again from e, and only the last one reaches the coda:

h(p)=F(e,g(h(p−1))),hfinal=C(e,h(3))

So the only way a state on the first pass can affect the output is by being passed on. Its lens, by the chain rule, is a product that crosses the gate twice:

Ja=𝔼x[∂C∂h(3)∂h(3)∂h(2)∂h(2)∂h(1)∂h(1)∂ha]

The middle two factors run entirely through g. A layer on the third pass keeps only the first factor and the last. The weights inside F are the same on every pass, but the factors to their left are not, which is why the same layer's lens changes so much from pass to pass.

Read through that chain, a first-pass state is measured mostly by what the next pass does with it, not by what it holds. To read what a pass holds, we run the model with the loop cut after p passes, so the coda reads that pass directly, and fit the lens there:

Ja(p)=𝔼x[∂C∂h(p)∂h(p)∂ha]

This is the lens we use for the first two passes; the third pass is the same in both.

Why each pass needs its own lens

Comparing the lens matrices entry by entry (cosine similarity, where 1 means identical and 0 unrelated) shows that gate chain at work. The same layer's pass-1 and pass-3 lenses are almost unrelated, and pass 2, one gate crossing away, sits in between.

How stable are the readings? Lenses fitted on two disjoint halves of the prompts agree on the top word for 65% to 95% of positions, depending on the pass. Scores are contrastive, measured against each word's average reading over ordinary text, so words that are always likely do not crowd out the ones specific to the prompt.

What does the model verbalize?

We ask Inkling 2 Mini to fill in the blank in “The chemical symbol of the metal with atomic number 79 is ____.” It answers Au. It never writes gold, the step in between, but gold is in the loop. It is the strongest reading under the word “79” by the second pass, and appears at the blank only after the loop.

It first appears under “79”. Before the loop, the state at “79” verbalizes atomic, nitrogen and neutron. On the first pass its strongest reading is chemist, and gold is already among the top three readings at layer 11. On the second pass gold is the strongest reading, in English and in Russian. On the third pass gold is still among the top readings at “79”.

The blank reads it on the third pass. On the third pass, the blank verbalizes chemical and symbol, in Russian, Arabic and Spanish, but not gold. Its answer still depends on the state at “79” on that pass. When we replace that state with the state from another question, the answer changes if we do it on the third pass and stays the same if we do it after the loop.

It is written only after the loop. In the first layer after the loop, the blank verbalizes gold in Russian, Vietnamese and English. It keeps verbalizing gold up to the second-to-last layer, and the model then writes Au.

The other questions follow the same route. kidney sits under “filter” from the first pass and reaches the blank only after the loop. cube sits under “faces” from the first pass, but the die question's blank never verbalizes it; it goes from quantity straight to twelve. The passages have no blank, so only the first step is visible, and it is the clearest one. When we read along the second pass of the wine passage, the line is almost a summary: woman, reject, drink, smile, conversation, doubt, touch, and under “stomach”, pregnancy.

Across many two-hop questions [13] that the model answers correctly without ever naming the middle step, such as “The author of the novel Animal Farm was born in the city of ____”, the lens reads the middle step inside the loop, as it read gold. At the word for the first entity, it reads the middle step on about a quarter of these questions, from the first pass on. At the last word, where the answer is produced, the middle step appears only on the third pass, and about three times as often when the model knows the first fact on its own. The answer position takes up the middle step once the earlier passes have formed it, and only when the model has the fact needed to form it.

In a standard transformer, the first hop of a two-hop question is resolved early, but the second hop starts too late in the network to use it. Copying a later state back into an earlier layer fixes many of these failures [14]. A loop does this by design, since every pass runs the middle layers again with the previous pass’s message as input. Our readings follow the same order. The middle entity appears at the entity’s word on the early passes, and the answer position takes it up on the third pass. Inkling 2 Mini needs the extra passes for this. With one pass it answers none of our two-hop questions correctly without writing, and with three passes it answers about three in ten. In other looped models, the middle entity also becomes readable after the first loop [15], and the last loop’s attention queries carry the second hop [16].

Our question is whether the loop holds these steps as words, and the lens reads the middle step at the answer position on only some of the questions. On the others, the step may be missing, or it may be present in a form that is not a word. A linear probe tells these cases apart, because it detects the middle entity in whatever form the state holds it. We train a probe to pick the middle entity out of candidates of the same kind, on questions where the model knows the first fact. At the answer position on the third pass, the probe finds the middle entity far more often than chance, while the lens reads it as a word much less often. After the loop, both find it. The answer position therefore carries the middle step on the third pass, and the model verbalizes it only after the loop.

On two-hop questions, the lens reads a country in the loop about half the time, but almost never a person, even when the name is the next word. A linear probe still finds people in the loop more reliably than any other kind of entity, so the loop carries them in a form the lens cannot read as a word. This comes from the layers rather than from looping, because TML-d24-varloop-research shows the same split when its middle layers run only once, and a simpler lens that compares each state with the model’s embedding of every word finds no people either. Reading the loop in words would therefore catch the countries in a hidden step and miss the people.

The loop also verbalizes numbers in long chains of thought before the model writes them. On an AIME problem, Inkling 2 Mini checks whether 1440*252 is 362880. At the multiplication sign, its second pass already verbalizes 500, a number the model writes 62 tokens later, in 720*500, when it checks the next case. We measure this across all the math problems in a later section.

Can we read the message between passes?

The middle step of a two-hop question forms at the entity’s word on the early passes and reaches the answer position on the third. Since each pass restarts from the prelude’s output, the step can only cross from one pass to the next through the message. At each word and loop layer, the message has four parts, which feed the next pass’s queries, keys, values and MLP. We fit a Jacobian lens to each part, so we can read what one pass sends to the next.

We read the messages on two-hop questions that the model answers without naming the middle entity. The message from the first pass to the second does not read as words. The message from the second pass to the third does, at the word that names the first entity, where it verbalizes the middle entity far more often than the middle entity of an unrelated question. The middle entity shows up only in the value part of the message, which later words read when they attend to this word.

The second pass writes the middle step into the value at the entity’s word, and on the third pass the answer position reads it from there through attention. The message carries less than the loop holds, since the third pass’s own state at that word verbalizes the middle entity more often than the message does.

In Huginn and Ouro, each loop hands its whole state to the next, and in Ouro the content does not cross in a form a linear lens can follow [17]. Inkling instead restarts every pass from the input and passes on only the gated message, so any reasoning that spans passes has to go through a small, fixed set of vectors. That makes the message a natural place to monitor a looped model. The lens reads only part of what crosses there. It finds the middle step some of the time, and only in the value part of the message.

We test causally whether the message carries the middle step by swapping messages between questions. We take pairs of questions about landmarks in different countries, one asking for the language and one for the currency. When we splice the third-pass messages of the currency question about Big Ben into “The language spoken in the country where the Eiffel Tower stands is”, the model answers pound instead of French. When we splice only the messages at the words after the landmark, it still answers French. The messages that change the answer are the ones at the landmark and before it, where the lens finds the middle step.

Steering the hidden step

A monitor that reads the loop needs its readings to be the ones the model acts on. The swap in the previous section replaces whole messages, which shows that the answer depends on what crosses at the landmark. To check that the model uses the word the lens reads there, we change only that word, by steering the state along the lens’s own directions. Steering on each pass in turn also shows when the model uses the step.

We use two-hop questions whose hidden step is a country, such as the capital of a writer’s birth country. On one pass, at the question’s subject, we move the state from the lens direction for the hidden country toward the lens direction for another country. On the third pass the answer switches to the other country’s in about half the questions, so London becomes Vienna. On the second pass it switches less often, and on the first pass or after the loop not at all, a window similar to the one in other looped models [17][18].

On the third pass, the lens direction switches the answer more often than the country’s ordinary output direction or the real difference between two questions’ states, and a random push of the same size almost never does.

The lens does not always read a step at the word the model takes it from. In the Carnival question, the lens reads Brazil at “celebrated” on the second and third passes, and only festival at “Carnival”. We copy third-pass states from a question about Holi that differs only in the festival. Copying the state at “celebrated” leaves the answer unchanged, while copying the state at “Carnival” switches the answer to the Holi question’s ocean. The model takes the step from “Carnival”, where the lens reads only festival. For a monitor, the word where a step is easiest to read is not always the word that drives the answer.

Where does the unwritten reasoning go?

With more passes, a looped model writes a shorter chain of thought [6]. We reproduce this with TML-d24-varloop-research [9], which runs one to five passes with the same weights. On GPQA Diamond [19] and on hard problems from MATH-500 [20][21] and AIME 2025 [22], three passes write about half as much reasoning as one pass and solve more of the problems.

Each extra pass is more computation before the next token, so a looped model can carry an intermediate result forward without writing it down [23]. If that is what happens, the steps the three-pass model skips should still be in its loop. We test this on the math problems. For each problem, we take the numbers the one-pass run writes in its working and the three-pass run never writes, and look for them among the readings of the three-pass loop. As a comparison, we look for the same numbers in the loop of a different problem.

Most of the numbers the three-pass model skips are still in its loop, nearly twice as often as in the loop of an unrelated problem. The numbers it does write are often in the loop before they appear, so the loop runs a few steps ahead of the text. Part of the working that one pass puts on the page, three passes do inside the loop, where the lens can still read it.

Running more passes than the model was trained for does not let it reason more in the loop. We run both models with one to eight passes and have them answer GPQA and two-hop questions directly, without writing any reasoning, so any gain has to come from the loop. Inkling 2 Mini, trained at three passes, does best at three and gets worse with more. TML-d24-varloop-research, trained at one to five, improves up to three or four passes and then levels off, even at eight. How much reasoning can leave the text is fixed in training and cannot be raised afterwards by running more passes.

Discussion

Looped transformers do think partly in words inside the loop. Inkling 2 Mini verbalizes many of the steps it never writes, on the pass where it forms them, and when TML-d24-varloop-research runs three passes instead of one, the numbers it stops writing are still in its loop. Looping moves reasoning from the text, where a monitor reads it, into the loop, where a lens can still read it.

This makes the loop a practical place to monitor. The Jacobian lens is fitted once from ordinary text without labels, and reading a state costs one matrix multiply and the model’s own output layer. In Inkling, every step that spans passes also has to cross the gated message, a small and fixed set of vectors that a monitor can read on every token.

A monitor built this way would have to handle three things we observe. The loop often verbalizes a concept in another language, so the monitor has to match concepts across languages. Some steps never become words in the loop, since a probe finds people there while the lens rarely reads them. The model can also take a step from a different word than the one where the lens shows it, as in the Carnival question. Reading the loop shows more of the reasoning than reading the text, and it still shows only part of it.

The loop holds intermediate steps and does not work out the final answer ahead of the text. On GPQA, the answer becomes readable in the loop only when the model is about to write it. Running more passes than the model was trained for does not let it reason more in the loop, so training fixes how much reasoning a model can keep out of its text. A model trained for many more passes could keep more of it out, and reading its loop would matter even more.

Related work

Looped models. Looping goes back to the Universal Transformer [4]. A few layers looped many times can match a much deeper model on reasoning tasks and can carry out a chain of thought inside their depth [23]. Huginn [5] and Ouro [24] scale looping to language models, and Coconut feeds hidden states back in place of written tokens [25]. Huginn and Ouro carry their state from one loop to the next, while Inkling 2 Mini restarts each pass from the prelude’s output and passes on only a gated message [6].

Reading intermediate states. The logit lens applies the output layer to an intermediate state [10], the tuned lens learns a correction for each layer [26], Patchscopes have the model describe a state in its own words [27], and the Jacobian lens carries a state to the output through the average linear response of the later layers [8]. Looped models have been harder to read. On Huginn, logit-lens readings change from one recurrent block to the next [28], and concepts placed into a looped model’s state are recognised only in the last loop [18]. The Jacobian lens finds a workspace in Ouro and Huginn that Ouro rebuilds in every loop [17], and on Inkling 2 Mini the logit lens works only where a pass ends [29]. We read Inkling 2 Mini pass by pass and also read the messages between passes.

Two-hop reasoning and monitoring. Models recall the middle entity of a two-hop question better than they use it [13], partly because the second hop starts too late in the network [14], and the hops combine more often for countries than for years [30]. In Ouro, the last loop’s attention queries carry the second hop [16]. The middle layers of multilingual models lean towards English [11][12][31]. Chain-of-thought monitoring relies on models writing out the reasoning they need [1], and training against a monitor teaches them to hide it [2]. Behavioural tests of looped models give a mixed picture [7].

Experimental details

Models. Inkling 2 Mini, a mixture-of-experts model with 26.4 billion parameters (3.4 billion active for each token), run with its trained three passes, and TML-d24-varloop-research, the same architecture trained at one to five passes.

Jacobian lens. For every layer on every pass, Ja is the average of ∂hfinal/∂ha over 128 WikiText prompts. Passes 1 and 2 are read with lenses fitted on the model run with only that many passes; pass 3 and the layers outside the loop with the lens of the full model. A reading is the log-probability of a word under WUJaha minus its mean at that layer over held-out text. Words in other languages are shown with their nearest English word in the unembedding space.

Message lens. Each loop layer on passes 2 and 3 receives a message from the previous pass in four parts (query, key, value and MLP inputs). For each of the 24 message sites and each part, J = E[∂hfinal/∂m], fitted with the main lens and read the same way.

Two-hop questions. 945 questions from TwoHopFact with a one-token middle entity, across 37 kinds of question, asked with the answer turn prefilled so the model answers without thinking. A question is answered silently when the answer is correct and the middle entity is not written. The lens or message lens finds the middle entity when it is among its top 10 words. Probe: ridge regression from the state to the model's own representation of the middle entity, five folds split by entity, scored by picking the right entity among candidates of the same kind.

State copying. 78 ordered pairs of questions from four templates that differ only in the subject. In the recipient's forward pass, the outputs at one word are replaced by the donor's, for one pass or after the loop.

Steering. 48 ordered pairs of questions from four templates. At the subject's last token, on one pass, h becomes h + α‖h‖·unit(dtarget − dsource), α ∈ {0.25, 0.5, 1, 2}, best α reported. Directions: JaTuw for the lens, with uw the country's output embedding; uw itself; the difference between the two questions' real states; or a random direction. The edit succeeds when the 8-token answer names the target question's answer.

Reasoning traces. GPQA Diamond (198 questions), MATH-500 level 5 (134) and AIME 2025 (30), sampled once per problem at temperature 1 with low reasoning effort, up to 6,144 (GPQA) or 8,192 (math) thinking tokens. GPQA questions are not shown, at the authors' request.

Unwritten reasoning. TML-d24-varloop-research at one and three passes, on the 132 MATH-500 level-5 and AIME 2025 problems both runs finish. Skipped numbers: number tokens in the one-pass thinking that are absent from the problem and from the whole three-pass output count as held if they are among the three-pass loop’s top 40 readings at any thinking position; the comparison checks the same numbers in another problem’s three-pass loop. Numbers about to be written: a number first written in the three-pass thinking and absent from the problem counts as held if it is among the loop’s top 40 readings in the 64 tokens before; the comparison checks the same number at the same relative point of another problem’s trace.

Pass sweep. All 198 GPQA questions and 300 two-hop questions, answered without thinking, at one to eight passes.
